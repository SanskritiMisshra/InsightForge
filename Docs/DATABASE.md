# InsightForge — Database Specification (DATABASE.md)

**Version:** 1.0
**Status:** Authoritative for the application database schema
**Database:** PostgreSQL 16
**Depends on:** `PRD.md` (§19, §29–30, §49–50, §61, §67–69, §79, §100–110, §112–114), `ARCHITECTURE.md` (§9, §10, §12, §17, §21)
**Migration tool:** Alembic (SQLAlchemy 2.x models mirror this document)

> This is the **application database** (metadata, metrics, insights, audit). It is **not** the analytical data store. User datasets live in object storage as Parquet and are queried through the DuckDB sandbox (`ARCHITECTURE.md` §10.5). The database stores **references and metadata only** (PRD §68).
>
> If this document conflicts with `PRD.md` or `ARCHITECTURE.md`, the conflict must be identified and resolved before implementation continues (PRD §127).

# 1. Scope and Principles

| # | Principle | Schema consequence |
|---|---|---|
| 1 | **Metadata only** | No dataset bodies, no large blobs; `storage_key` + checksum + size instead |
| 2 | **Raw data immutable, versions append-only** | Immutability triggers on `dataset_versions`; no UPDATE of content fields |
| 3 | **One source of numeric truth** | `metrics` table is the sole store of computed numbers; insights/reports reference metric IDs |
| 4 | **Every result is traceable** | Metrics, insights, reports carry `run_id`, `dataset_version_id`, `pipeline_version`, `config_hash` |
| 5 | **Ownership enforced structurally** | `owner_id` on every owned root; composite FKs make cross-tenant references impossible |
| 6 | **Reproducible runs** | `analysis_runs.run_key` unique over (dataset version, config, mapping, pipeline version, domain) |
| 7 | **Auditable** | Append-only, partitioned `audit_events` |
| 8 | **Safe deletion** | Projects soft-delete; `ON DELETE RESTRICT` on dependency edges (PRD §108–109) |
| 9 | **Idempotent writes** | Natural/unique keys + `UPSERT` semantics for stage outputs (PRD §103–104) |
| 10 | **Precision preserved** | `NUMERIC` for metric values; formatting only at presentation (PRD §114) |

# 2. Conventions

## 2.1 Naming
- Tables: `snake_case`, plural (`projects`, `dataset_versions`).
- Columns: `snake_case`; foreign keys `<entity>_id`; booleans `is_*` / `has_*`; timestamps `*_at`.
- Constraints: `pk_<table>`, `fk_<table>__<ref>`, `uq_<table>__<cols>`, `ck_<table>__<rule>`, `ix_<table>__<cols>`.

## 2.2 Types
| Concern | Type | Notes |
|---|---|---|
| Primary keys | `uuid` | **UUIDv7** generated by the application (time-ordered). DB default `uuid_generate_v7()` fallback (§3.2) |
| Timestamps | `timestamptz` | Always UTC; `created_at DEFAULT now()` |
| Enumerations | `text` + `CHECK` | Easier migrations than native enums (§4) |
| Case-insensitive text | `citext` | Emails |
| Money/metric values | `numeric(38,10)` | Pending ADR-016; never `float` for reported values |
| Variable structure | `jsonb` | Only for genuinely variable payloads (stage counts, config, dimensions) |
| Hashes | `text` (`sha256:<hex>`) | Fixed prefix for algorithm agility |
| Sizes/counts | `bigint` | |
| Percentages | `numeric(7,4)` | Stored as 0–100 |

## 2.3 Standard columns
Every mutable table has `created_at timestamptz NOT NULL DEFAULT now()` and `updated_at timestamptz NOT NULL DEFAULT now()` (maintained by trigger `trg_set_updated_at`). Append-only tables (`metrics`, `audit_events`, `stage_runs` history) omit `updated_at` where noted.

## 2.4 Tenancy
`owner_id uuid NOT NULL REFERENCES users(id)` on every user-owned root and high-traffic child. Composite foreign keys `(parent_id, owner_id)` guarantee a child can never point to another user's parent.

## 3.2 Helper functions

```sql
-- UUIDv7 fallback (application normally supplies ids; PG18+ has native uuidv7())
CREATE OR REPLACE FUNCTION uuid_generate_v7() RETURNS uuid AS $$
DECLARE
  ts_ms bigint := (extract(epoch FROM clock_timestamp()) * 1000)::bigint;
  rnd   bytea  := gen_random_bytes(10);
  b     bytea;
BEGIN
  b := decode(lpad(to_hex(ts_ms), 12, '0'), 'hex') || rnd;
  -- set version (7) and variant (10xx)
  b := set_byte(b, 6, (get_byte(b, 6) & 15) | 112);
  b := set_byte(b, 8, (get_byte(b, 8) & 63) | 128);
  RETURN encode(b, 'hex')::uuid;
END;
$$ LANGUAGE plpgsql VOLATILE;

CREATE OR REPLACE FUNCTION trg_set_updated_at() RETURNS trigger AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE OR REPLACE FUNCTION trg_forbid_update_delete() RETURNS trigger AS $$
BEGIN
  RAISE EXCEPTION '% on % is not permitted (append-only table)', TG_OP, TG_TABLE_NAME
    USING ERRCODE = 'integrity_constraint_violation';
END;
$$ LANGUAGE plpgsql;
```

## 3.3 Database roles

| Role | Used by | Privileges |
|---|---|---|
| `if_migrator` | Alembic / deploy job | DDL on schema `public`; owner of objects |
| `if_api` | FastAPI | `SELECT/INSERT/UPDATE/DELETE` on application tables; `INSERT` only on `audit_events`; no DDL |
| `if_worker` | Celery workers | Same as `if_api` plus write on run-output tables; no access to `sessions`, `password_reset_tokens` |
| `if_readonly` | BI/ops read replicas | `SELECT` on non-sensitive tables (no `users.password_hash`, no sessions) |

```sql
REVOKE ALL ON ALL TABLES IN SCHEMA public FROM PUBLIC;
-- grants are applied per role in migration `0002_grants` (see §14)
```

The **SQL analytics sandbox has no database credentials at all** (`ARCHITECTURE.md` §10.5).

# 5. Entity-Relationship Overview

```text
users ─┬─< oauth_accounts
       ├─< sessions
       ├─< password_reset_tokens
       ├─< notifications
       ├─< retention_policies
       └─< projects ─┬─< datasets ─< dataset_versions ─┬─< dataset_columns
                     │                    │            ├── dataset_profiles (1:1)
                     │                    │            └─< cleaning_operation_sets ─< cleaning_operations
                     │                    │
                     │                    └──────────────┐ (parent_version_id self-ref lineage)
                     │
                     └─< analysis_runs ─┬─< stage_runs
                                        ├─< module_availability
                                        ├── data_quality_reports (1:1) ─< quality_issues
                                        ├─< eda_results
                                        ├─< metrics ───────────┐
                                        ├─< sql_queries ◄──────┤ (metric.sql_query_id)
                                        ├─< insights ─< insight_metrics >─ metrics
                                        │       └─< recommendation_sources >─ recommendations
                                        ├─< recommendations
                                        ├─< reports
                                        ├─< presentations
                                        ├─< powerbi_models
                                        └─< exports
jobs (→ analysis_runs, optional)      idempotency_keys      audit_events (partitioned)
```

Cardinality highlights:
- A **project** has many datasets; one is the **active dataset** (`projects.active_dataset_id`).
- A **dataset** has an ordered chain of **immutable versions**; version 1 is the ingested original.
- An **analysis run** references **exactly one** dataset version and is unique per run key.
- **Metrics** belong to one run; **insights** cite metrics through `insight_metrics`.

```sql
  preferences        jsonb  NOT NULL DEFAULT '{}'::jsonb,    -- currency, density, notifications (non-sensitive UI prefs)
  last_login_at      timestamptz,
  failed_login_count integer NOT NULL DEFAULT 0,
  locked_until       timestamptz,
  created_at         timestamptz NOT NULL DEFAULT now(),
  updated_at         timestamptz NOT NULL DEFAULT now(),
  deleted_at         timestamptz,
  CONSTRAINT uq_users__email UNIQUE (email),
  CONSTRAINT ck_users__status CHECK (status IN ('ACTIVE','SUSPENDED','DELETED')),
  CONSTRAINT ck_users__name_len CHECK (char_length(name) BETWEEN 1 AND 120),
  CONSTRAINT ck_users__auth_present CHECK (password_hash IS NOT NULL OR deleted_at IS NOT NULL OR true)

-- Google-only users have NULL password_hash; presence of a credential is verified at the service layer
-- (oauth_accounts row exists) and covered by integration tests.

CREATE TABLE sessions (

  revoked_at         timestamptz,

  csrf_secret_hash   text
);
CREATE INDEX ix_sessions__user_active ON sessions (user_id) WHERE revoked_at IS NULL;
CREATE INDEX ix_sessions__expiry ON sessions (absolute_expires_at);

  id          uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash  text NOT NULL UNIQUE,                          -- hashed; single-use
  expires_at  timestamptz NOT NULL,
  used_at     timestamptz,
  created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ix_password_reset_tokens__user ON password_reset_tokens (user_id);
```

> Sessions are primarily served from Redis for speed; this table is the durable record used for validation fallback, "sign out everywhere", and audit (`ARCHITECTURE.md` §12.1).

```sql
ALTER TABLE projects

CREATE TABLE dataset_versions (
  id                    uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  dataset_id            uuid NOT NULL,
  owner_id              uuid NOT NULL,
  version_number        integer NOT NULL,
  kind                  text NOT NULL,
  parent_version_id     uuid REFERENCES dataset_versions(id) ON DELETE RESTRICT,
  storage_key           text NOT NULL,                       -- Parquet object key
  content_sha256        text NOT NULL,                       -- verified on every worker load
  size_bytes            bigint NOT NULL,
  row_count             bigint NOT NULL,
  column_count          integer NOT NULL,
  label                 text,                                -- "Original", "After cleaning", …
  operation_set_id      uuid,                                -- cleaning/transform set that produced it (FK below)
  created_by            uuid REFERENCES users(id),
  created_at            timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_dataset_versions__id_owner UNIQUE (id, owner_id),
  CONSTRAINT uq_dataset_versions__dataset_number UNIQUE (dataset_id, version_number),
  CONSTRAINT fk_dataset_versions__dataset FOREIGN KEY (dataset_id, owner_id)
    REFERENCES datasets (id, owner_id) ON DELETE RESTRICT,
  CONSTRAINT ck_dataset_versions__kind CHECK (kind IN ('ORIGINAL','CLEANED','TRANSFORMED')),
  CONSTRAINT ck_dataset_versions__number CHECK (version_number >= 1),
  CONSTRAINT ck_dataset_versions__lineage CHECK (
    (version_number = 1 AND parent_version_id IS NULL AND kind = 'ORIGINAL') OR
    (version_number > 1 AND parent_version_id IS NOT NULL AND kind <> 'ORIGINAL')),
  CONSTRAINT ck_dataset_versions__hash CHECK (content_sha256 ~ '^sha256:[0-9a-f]{64}$'),
  CONSTRAINT ck_dataset_versions__counts CHECK (row_count >= 0 AND column_count >= 1 AND size_bytes > 0)
);
CREATE INDEX ix_dataset_versions__dataset ON dataset_versions (dataset_id, version_number DESC);
CREATE INDEX ix_dataset_versions__parent  ON dataset_versions (parent_version_id);

-- Immutability (PRD §29–30): content-defining columns can never change after insert.
CREATE OR REPLACE FUNCTION trg_dataset_versions_immutable() RETURNS trigger AS $$
BEGIN
  IF NEW.dataset_id        IS DISTINCT FROM OLD.dataset_id
  OR NEW.owner_id          IS DISTINCT FROM OLD.owner_id
  OR NEW.version_number    IS DISTINCT FROM OLD.version_number
  OR NEW.kind              IS DISTINCT FROM OLD.kind
  OR NEW.parent_version_id IS DISTINCT FROM OLD.parent_version_id
  OR NEW.storage_key       IS DISTINCT FROM OLD.storage_key
  OR NEW.content_sha256    IS DISTINCT FROM OLD.content_sha256
  OR NEW.size_bytes        IS DISTINCT FROM OLD.size_bytes
  OR NEW.row_count         IS DISTINCT FROM OLD.row_count
  OR NEW.column_count      IS DISTINCT FROM OLD.column_count THEN
    RAISE EXCEPTION 'dataset_versions content columns are immutable'
      USING ERRCODE = 'integrity_constraint_violation';
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
CREATE TRIGGER trg_dataset_versions_immutable BEFORE UPDATE ON dataset_versions
  FOR EACH ROW EXECUTE FUNCTION trg_dataset_versions_immutable();
```

> Only `label`, `operation_set_id` (set once), and `created_by` metadata may be edited. Hard deletion of a version occurs only through the retention purge procedure (§12.3), which temporarily disables nothing — it deletes in dependency order as the privileged `if_migrator`-owned purge function.

## 6.4 Cleaning operations

```sql
CREATE TABLE cleaning_operation_sets (
  id                 uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
```

```sql
CREATE OR REPLACE FUNCTION trg_insight_requires_evidence() RETURNS trigger AS $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM insight_metrics WHERE insight_id = NEW.id) THEN
    RAISE EXCEPTION 'insight % has no evidence metrics', NEW.id
      USING ERRCODE = 'integrity_constraint_violation';
  END IF;
  RETURN NULL;
END;
$$ LANGUAGE plpgsql;
```

# 8. Integrity Rules Summary

| Rule | Mechanism |
|---|---|
| A child can never reference another user's parent | Composite FKs `(id, owner_id)` |
| Raw/clean versions are immutable | `trg_dataset_versions_immutable` |
| Version chain valid (v1 original, others have parent) | `ck_dataset_versions__lineage` |
| One run per (project, run_key) while live | `uq_analysis_runs__project_runkey_live` |
| Terminal runs have `finished_at`; failed runs have error code | `ck_analysis_runs__terminal`, `__error` |
| Unavailable modules always carry a reason | `ck_module_availability__reason` |
| Skipped EDA results always carry a reason | `ck_eda_results__reason` |
| Metrics cannot be edited after write | `trg_metrics_no_update` |
| Currency metrics carry a currency | `ck_metrics__currency` |
| Every insight has evidence; every recommendation has a source insight | Deferred constraint trigger + service tests |
| Audit log cannot be altered | `trg_audit_events_append_only` + no DELETE/UPDATE grants |

| Links in notifications stay in-app | `ck_notifications__link` |

# 9. Indexing Strategy

Principles:
1. Index every foreign key used in joins or cascades.
2. Prefer **partial indexes** on `deleted_at IS NULL` and active-status filters.
3. Composite indexes lead with the **tenant/owner or parent key**, then sort key (`created_at DESC`).
4. GIN only where JSONB containment is queried (`metrics.dimensions`) and for trigram name search.
5. No speculative indexes; each index must map to a documented query pattern (§10) and be reviewed with `EXPLAIN` in CI for hot paths.

Hot-path coverage:

| Query pattern | Index |
|---|---|
| Dashboard recent projects | `ix_projects__owner_updated` |
| Project list filtered by status | `ix_projects__owner_status` |
| Project detail → active run | `ix_analysis_runs__project` |
| Poll/stream progress | PK on `analysis_runs`, `ix_stage_runs__run` |
| Evidence drawer: metric by run+name | `ix_metrics__run_name` / unique `(run_id, metric_name, dimension_key)` |
| Insights page by theme | `ix_insights__run_theme` |
| SQL history | `ix_sql_queries__project` |
| Unread notifications badge | `ix_notifications__user_unread` |
| Retention scans | `ix_reports__expiry`, `ix_exports__expiry`, `ix_projects__purge`, `ix_idempotency_keys__expiry` |
| Audit by project/actor/resource | `ix_audit_events__*` (per partition) |
| Duplicate upload hint | `ix_datasets__checksum` |

# 10. Representative Query Patterns

All examples are **owner-scoped**; repositories never expose unscoped lookups for owned entities.

```sql
-- Dashboard: recent projects with latest run progress (PRD §14)
SELECT p.id, p.name, p.status, p.updated_at,
       d.original_filename,
       r.status AS run_status, r.progress_pct
FROM projects p
LEFT JOIN datasets d ON d.id = p.active_dataset_id
LEFT JOIN LATERAL (
  SELECT status, progress_pct FROM analysis_runs
  WHERE project_id = p.id ORDER BY created_at DESC LIMIT 1
) r ON true
WHERE p.owner_id = $1 AND p.deleted_at IS NULL
ORDER BY p.updated_at DESC
LIMIT 8;

-- Overview KPIs (PRD §14.1)
SELECT
  (SELECT count(*) FROM projects  WHERE owner_id=$1 AND deleted_at IS NULL)               AS total_projects,
  (SELECT count(*) FROM datasets  WHERE owner_id=$1 AND deleted_at IS NULL)               AS total_datasets,
  (SELECT count(*) FROM analysis_runs WHERE owner_id=$1 AND status='COMPLETED')           AS completed_analyses,
  (SELECT count(*) FROM reports   WHERE owner_id=$1 AND status='READY')                   AS generated_reports,
  (SELECT count(*) FROM insights i JOIN analysis_runs r ON r.id=i.run_id WHERE r.owner_id=$1) AS generated_insights;

-- Evidence drawer: metric + its SQL + provenance (PRD §50, §131)
SELECT m.metric_name, m.value, m.unit, m.currency, m.calculation, m.pipeline_version,
       m.computed_at, dv.version_number, dv.content_sha256, q.sql_text
FROM metrics m
JOIN analysis_runs r      ON r.id = m.run_id AND r.owner_id = $1
JOIN dataset_versions dv  ON dv.id = m.dataset_version_id
LEFT JOIN sql_queries q   ON q.id = m.sql_query_id
WHERE m.id = $2;

-- Insight with evidence metrics
SELECT i.*, jsonb_agg(jsonb_build_object('metric_id', m.id, 'name', m.metric_name, 'value', m.value)) AS metrics
FROM insights i
JOIN insight_metrics im ON im.insight_id = i.id
JOIN metrics m          ON m.id = im.metric_id
JOIN analysis_runs r    ON r.id = i.run_id AND r.owner_id = $1
WHERE i.run_id = $2
GROUP BY i.id
ORDER BY i.impact_rank NULLS LAST;

-- Idempotent run creation (PRD §104)
INSERT INTO analysis_runs (project_id, owner_id, dataset_version_id, run_key, domain_key,
                           pipeline_version, config, config_hash, mapping_hash, requested_by)
VALUES ($1,$2,$3,$4,$5,$6,$7,$8,$9,$2)
ON CONFLICT (project_id, run_key) WHERE status IN ('QUEUED','RUNNING','COMPLETED')
DO UPDATE SET updated_at = analysis_runs.updated_at       -- no-op that lets RETURNING yield the existing row
RETURNING *;

-- Dependency check before dataset delete (PRD §109)
SELECT 'analysis_runs' AS dependent, count(*) FROM analysis_runs ar
  JOIN dataset_versions dv ON dv.id = ar.dataset_version_id WHERE dv.dataset_id = $1
UNION ALL
SELECT 'reports', count(*) FROM reports rp JOIN analysis_runs ar ON ar.id = rp.run_id
  JOIN dataset_versions dv ON dv.id = ar.dataset_version_id WHERE dv.dataset_id = $1;

-- Keyset pagination for projects
SELECT id, name, status, updated_at FROM projects
WHERE owner_id = $1 AND deleted_at IS NULL
  AND (updated_at, id) < ($2, $3)
ORDER BY updated_at DESC, id DESC
LIMIT 25;
```

# 11. Row-Level Security (Defense in Depth — P1 Hardening, ADR-015)

Application-layer scoping and composite FKs are **mandatory**. RLS is an optional additional layer, designed now so it can be enabled without schema changes.

# 12. Lifecycle, Deletion, and Retention (PRD §108–110)

## 12.1 Soft delete
- **Projects:** `deleted_at` set; `purge_after = deleted_at + grace period` (default 30 days). Soft-deleted projects are hidden everywhere (all queries filter `deleted_at IS NULL`), restorable until purge.
- **Datasets:** `deleted_at` allowed only when no *live* dependent runs/reports exist, or the user confirms cascade (service-level, listing dependents per §10).
- **Users:** account deletion sets `deleted_at`, revokes sessions, and schedules purge of owned data; `audit_events` retain `actor_user_id` as an orphaned reference (no FK) with metadata only.

## 12.2 Retention jobs (Celery `light` queue, nightly)

| Target | Rule |
|---|---|
| `sessions` | Delete where `absolute_expires_at < now() - interval '7 days'` or `revoked_at < now() - interval '30 days'` |
| `password_reset_tokens` | Delete expired/used older than 7 days |
| `idempotency_keys` | Delete where `expires_at < now()` |
| `reports` / `presentations` / `exports` / `powerbi_models` | Per `retention_policies(GENERATED_FILE)`: mark `EXPIRED`, delete object, keep the row (regenerable from the run) |
| Failed jobs/runs artifacts | Per `retention_policies(FAILED_JOB)` |
| `notifications` | Delete read notifications older than 90 days |
| `audit_events` | Drop whole partitions older than policy (default 365 days) |
| Temp objects | Handled by object-store lifecycle rules (24h) |

## 12.3 Purge procedure (hard delete)

Executed by a privileged function `purge_project(p_project_id uuid)` owned by `if_migrator`, invoked by the retention job after `purge_after`:

```text
1. Verify deleted_at IS NOT NULL AND purge_after <= now()
2. Collect all object-storage keys (datasets, versions, derived, reports, decks, exports, powerbi, sql results)
   → enqueue object deletions (idempotent) BEFORE deleting rows
3. Delete in dependency order inside one transaction:
   insight_metrics → recommendation_sources → recommendations → insights → metrics
   → sql_queries → eda_results → quality_issues → data_quality_reports → module_availability
   → stage_runs → jobs → reports/presentations/powerbi_models/exports → analysis_runs
   → cleaning_operations → cleaning_operation_sets(clear dataset_versions.operation_set_id first)
   → dataset_columns/dataset_profiles → dataset_versions (children before parents by version_number DESC)
   → datasets → projects
4. Write audit event project.purged (metadata: counts only)
```

Object deletion failures are retried; DB rows are only removed once the object-deletion tasks are durably enqueued, and a reconciliation job lists orphaned objects (keys with no row) weekly.

# 13. Concurrency and Transactions

| Concern | Strategy |
|---|---|
| Isolation | Default `READ COMMITTED`; use `SERIALIZABLE` / explicit locks only where noted |
| Version creation | `pg_advisory_xact_lock(hashtext(dataset_id::text))` while computing `version_number = max+1` to avoid races (PRD §30; `ARCHITECTURE.md` §9.7) |
| Run creation | Single `INSERT … ON CONFLICT` (idempotent, §10) |
| Stage outputs | Written in one transaction with the `stage_runs` status update; replays `UPSERT` on `(run_id, stage)` / `(run_id, metric_name, dimension_key)` |
| Progress updates | `UPDATE analysis_runs SET progress_pct …` throttled (≥ 1% or ≥ 1s) to reduce write amplification; Redis carries high-frequency progress |
| Cancellation | `cancel_requested_at` set by API; workers poll at safe checkpoints |
| Optimistic concurrency (user edits) | `updated_at` compared (`If-Match`/ETag derived from `updated_at`) on `projects`, `dataset_columns` mapping edits |
| Connection pooling | PgBouncer (transaction mode) in production; async SQLAlchemy pool sized per service; `statement_timeout` = 15s for API, 120s for workers; `idle_in_transaction_session_timeout` = 30s |

# 15. Migration Policy (Alembic)

1. **Linear history**, one migration per logical change, named `NNNN_description.py`.
2. **Expand → migrate → contract** for any change affecting running code:
   - Expand: add nullable columns/new tables/new indexes (`CREATE INDEX CONCURRENTLY`).
   - Migrate: backfill in batches (never one giant transaction on large tables).
   - Contract: drop old columns only after a release where no code reads them.
3. **Backward compatible** with the previous application version (rolling deploys; `ARCHITECTURE.md` §16.2).
4. **Reversible** (`downgrade`) unless explicitly flagged `irreversible` with justification in the PR.
5. **Enum/CHECK changes** are two-step: add the new allowed value (`NOT VALID` then `VALIDATE`), deploy code, later remove retired values.
6. **Locks:** migrations set `lock_timeout = '5s'` and `statement_timeout`; long operations are split.
7. **CI:** migrations run on an empty DB and on a restored production-shaped snapshot (staging); a schema-drift check compares SQLAlchemy models to the migrated schema.
8. **Seed data:** only reference/config rows (e.g., default `retention_policies`); demo data lives in a separate script (`scripts/seed_demo.py`), never in migrations.
9. **Pipeline version coupling:** changing metric definitions does **not** require a schema migration, but bumps `PIPELINE_VERSION`; the DB records which version produced each result.

Initial migration sequence:

# 16. Testing the Database Layer (PRD §80)

| Test | Purpose |
|---|---|
| **Migration up/down/up** on empty DB | Reversibility and idempotent DDL |
| **Schema-drift test** | ORM models ≡ migrated schema |
| **Constraint tests** | Each `CHECK`, unique index, and trigger has a test proving a violating insert/update fails (e.g., editing `content_sha256` fails; `FAILED` run without `error_code` fails; unavailable module without reason fails) |
| **Cross-tenant matrix** | For every owned table/endpoint: user A cannot read/write user B's rows; composite FK prevents cross-tenant references even with forged IDs |
| **Idempotency tests** | Concurrent duplicate run creation yields one row; concurrent report generation yields one `READY` artifact |
| **Immutability tests** | `metrics` and `audit_events` reject UPDATE/DELETE from application roles |
| **Lineage tests** | Version chain validity; `version_number` assigned without gaps/duplicates under concurrency |
| **Purge tests** | `purge_project` removes all dependents, leaves no orphans, enqueues all object deletions |
| **Retention tests** | Expired rows/objects handled per policy; partitions dropped correctly |
| **Performance tests** | `EXPLAIN` assertions for hot-path queries (§10) on a 5M-row `metrics`/1M-row `audit_events` synthetic dataset |
| **Property tests** | Evidence rule: every inserted insight has ≥ 1 `insight_metrics` row at commit |
| **Rollback safety** | Migration applied against a snapshot while old app version runs integration smoke tests |

# 17. Capacity and Operations

## 17.1 Sizing assumptions (V1, order-of-magnitude)

| Table | Growth driver | Estimate per completed run |
|---|---|---|
| `metrics` | Dimensional breakdowns | 200–5,000 rows (bounded by top-N policies) |
| `insights` / `recommendations` | Rule outputs | 10–60 / 5–40 |
| `sql_queries` | Templated + user queries | 30–200 |
| `quality_issues` | Per-column findings | 10–200 |
| `audit_events` | User/system actions | 50–500 per run lifecycle |
| `dataset_columns` | Columns × versions | 10–100 per version |

At 10,000 runs, `metrics` stays in the low tens of millions of rows — comfortably within a single PostgreSQL instance with proper indexes. If growth exceeds this, partition `metrics` by `run_id` hash or time (documented path; no schema redesign needed).

## 17.2 Operations

- **Backups:** continuous WAL archiving + daily base backups; point-in-time recovery tested quarterly. Object-store versioning backs up derived artifacts; raw datasets use object lock.
- **High availability:** managed Postgres with a synchronous/near-synchronous standby; read replica for `if_readonly`.
- **Maintenance:** autovacuum tuned for high-churn tables (`analysis_runs`, `stage_runs`, `jobs`, `sessions`); `idempotency_keys`/`sessions` cleaned by retention jobs; monitor bloat and long transactions.
- **Monitoring:** connection saturation, replication lag, slow-query log (`log_min_duration_statement = 500ms`), lock waits, table/index bloat, partition coverage (alert if rows hit `audit_events_default`).
- **Security:** TLS-only connections, least-privilege roles (§3.3, §14), credentials via secret manager, no superuser use by services, audit of DDL.
